# CLAUDE.md — правила работы с проектом CarService1 / AutoDuck

## ⚠️ Главное правило: синхронизация с ТЗ

**При КАЖДОМ изменении кода обязательно обновляй техническое задание.**

- Полное ТЗ — [`docs/SPECIFICATION.md`](docs/SPECIFICATION.md). Это источник
  истины. Любая правка, влияющая на поведение продукта, должна быть отражена
  в нём **в том же коммите**, что и сам код.
- Если правка видна пользователю или меняет запуск/настройку — обнови ещё и
  [`README.md`](README.md).

### Что считается изменением, требующим правки ТЗ
Обновляй `docs/SPECIFICATION.md`, если меняешь хоть что-то из списка:
- экран добавлен/удалён/переименован или изменился его маршрут → §6, §8;
- изменились элементы, состояния, взаимодействия или критерии приёмки
  экрана → соответствующий подраздел §8;
- добавлен/изменён компонент или его props → §9;
- изменилась модель данных (типы `types/index.ts` или SQL) → §7;
- изменился стор, сервис (`lib/*`) или конфиг → §10, §11, §14;
- добавлены/изменены дизайн-токены → §4;
- изменилась навигация/адаптивность → §5;
- добавлены/изменены i18n-ключи → §13 (и все три файла `i18n/*.json`).

### Порядок действий при любой задаче
1. Внеси изменения в код.
2. Сразу обнови `docs/SPECIFICATION.md` (и `README.md` при необходимости).
3. Прогони `npm run typecheck` — без ошибок.
4. Коммить кодом и обновлённым ТЗ вместе, одним коммитом.

> Если ТЗ и код разошлись — это баг. Приоритет: привести ТЗ в соответствие
> с фактическим поведением.

## Конвенции проекта

- Цвета — только через `Palette` (`constants/theme.ts`), без сырых HEX в экранах.
- Любой видимый текст — только через `t()` (i18next); новые ключи добавлять
  одновременно в `i18n/en.json`, `ru.json`, `pt-BR.json`.
- Адаптивность — через `useResponsive()` и layout-примитивы (`Page`, `Grid`,
  `AppShell`); не плодить отдельные desktop/mobile экраны.
- Перед коммитом: `npm run typecheck` зелёный, web-сборка собирается.
- Ветка разработки: `claude/lucid-clarke-R2Ng6`. Пушить только в неё.

## Полезные команды

```bash
npm run typecheck                 # tsc --noEmit (strict)
EXPO_OFFLINE=1 npx expo start --web   # запуск web (в т.ч. в офлайн-средах)
```
